# 项目任务书：开源 2D Mini Studio（Concat_camera 分支实战版）

你现在担任这个项目的首席软件架构师、技术负责人、UI/UX 设计师和核心开发工程师。

你的任务是基于现有开源仓库 `xmp777/Concat_camera`（Fork 自 `jub0t/Concat`）设计并逐步开发一款 Windows 桌面软件。

暂定项目名称：**2D Mini Studio**。

这是一款面向 2D 动画、日式角色互动、角色对话和小剧场制作的创作软件。

核心定位：

**剪映式易用性 + 完整 2D 场景编辑 + 虚拟摄像机 + 智能资产管理 + 本地 AI + Agent 自动化。**

这不是一个普通的视频剪辑器，也不是一个简单的图片合成器，而是一个专门服务于 2D 小剧场制作的创作工作站。

> **当前状态说明（2026-11-19）**：技术栈已锁定为 **Rust + Concat**；`concat-camera`（虚拟摄像机）、`concat-scene`（2D 场景）、`concat-studio`（无头渲染）、MCP `scene_render` 已完成并验证；MSVC 为正式基线。详见 `docs/HANDOVER.md` 与 `docs/CAMERA_DESIGN.md`。

# 一、最高优先级：先审计、后开发（Phase 0）

技术栈基座已锁定为 **Rust + Concat 架构**（不再调研 Qt 6、MLT 或 C++/C# 跨语言重型框架）。在编写大规模业务代码之前，必须先完成对 `Concat` 现有代码的深度审计及 Rust 生态轻量组件的仓库级调研。

不要仅仅依赖已有知识或搜索结果摘要，必须实际检查本地仓库代码与 GitHub 仓库源码。

## 1.1 代码基座审计与 Rust 生态调研

重点检查与调研以下方向：

1. **`Concat` 现有代码审计**：梳理 `jub0t/Concat` 的 Crate/模块划分、时间轴数据结构、FFmpeg 渲染管线、Slint UI 架构、Undo/Redo 机制及现有工程序列化格式。
   > **已完成**：`docs/HANDOVER.md`、`docs/CAMERA_DESIGN.md` 已记录。
2. **2D 场景与虚拟摄像机渲染路径**（已锁定）：**不自建 2D 渲染引擎**；场景图层经 `concat-scene` 求值后输出 `Transform`，交由 Concat 的合成器/导出管线。仅当需要自绘图形（rect/ellipse/line）时，再评估 `tiny-skia` / `image` 做素材化，不用于场景渲染。
3. **关键帧与缓动曲线**：直接复用 `concat-core::animate::Ease`（三次贝塞尔）。不再评估外部插值库。
4. **本地数据存储**：`rusqlite`（SQLite 资产元数据）+ `serde_json`（工程序列化与 Schema 迁移）。
5. **本地语音识别（ASR）**：优先复用 `concat-speech`（whisper.cpp）；`faster-whisper` 作为可选 GPU 增强（Python sidecar）。
6. **MCP Server 与 Agent 自动化**：扩展现有 `concat-mcp`（Schema 由 `concat-api` 请求类型生成）；不引入 `rmcp`。
7. **互操作标准参考**：参考 `OpenTimelineIO` 的时间轴概念模型（无需强行引入其 C++/Python 运行时）。

对每个引入的第三方库记录：

- GitHub Stars 及查询日期。
- 最近更新时间与 Release 活跃度。
- Windows（GNU 与 MSVC）编译兼容性。
- 许可证（重点排查 GPL、AGPL、LGPL、MIT、Apache-2.0 兼容性）。
- 是否存在维护停滞、依赖冲突或性能风险。

核心原则：

**充分复用 Concat 已有媒体管线与成熟 Rust Crate，只有当现有方案无法满足 2D 场景与虚拟摄像机需求时才自行开发。**

# 二、项目设计原则与环境约束

1. **分支策略**：`main` 为产品主线（承载我们的功能），定期从 `upstream`（`jub0t/Concat`）合并；可选的功能分支用于大型改动，合并回 main 前必须通过全部测试。禁止对 main 使用 force-push。
2. **Windows 10/11 优先**：确保在 Windows 桌面环境下开箱即用。
3. **编译链策略**：**MSVC 为正式基线**（VS Build Tools 2022 + `vcvars64.bat`）；GNU（MSYS2 UCRT64）作为备用快速通道，但发布与 CI 以 MSVC 为准。
4. **完全开源与本地优先**：不依赖云端服务即可完成全部核心创作与导出工作。
5. **AI 服务可选**：不绑定单一大模型供应商；无 AI / 断网状态下软件所有基础功能必须 100% 可用。
6. **Agent 是一等使用者**：所有核心能力必须先有结构化 API/MCP 接口，再有 UI 交互。
7. **工程文件结构化**：基于 Concat 原生 JSON 向后兼容扩展，可读、可 diff、可由 Agent 直接生成与修改。
8. **完整撤销与重做**：复用 `concat-project` 的 Command 栈；新增功能必须通过命令路径进入 Undo/Redo，不绕过。
9. **架构解耦与代码整洁**：UI（Slint）与核心业务逻辑（Core Engine）严格分离；禁止巨型文件、禁止用临时脚本代替正式架构、禁止无法解释的重复代码。

**开发与运行硬件约束（NVIDIA RTX 4060 8GB 显存）：**

- 本地 ASR 等 AI 推理优先支持 CUDA 加速。
- 显存不足或无独立显卡环境时，必须自动回退至 CPU 或低显存量化模式。
- 禁止让本地 AI 模型常驻占用全部显存，避免与 GPU 2D 渲染争抢资源。

# 三、核心技术架构（已锁定基座）

## 3.1 桌面 UI 框架：Slint UI

沿用 `Concat` 现有的 **Slint** 声明式 UI 框架，不引入 Qt 或 WebView。

- **开发策略**：前期采用极简预览窗口与调试面板优先验证核心引擎；中后期构建现代化的可停靠多面板工作区。
- **注意**：Slint **没有现成的可停靠工作区组件**（无 QtADS 类库）。Phase 4 的停靠/浮动/标签合并/工作区保存需要自建（先做 Spike），或采用多窗口/标签页策略作为替代。

## 3.2 视频与媒体引擎：Concat Rust + FFmpeg 管线

直接复用 `Concat` 现有的媒体解码、音频混音、时间轴合成与 FFmpeg 视频编码能力。

- 严禁从零重写音视频编解码器。
- 2D 场景引擎**不作为独立的帧生产者**，而是作为图层数据源：经 `concat-scene::plan_layers` 输出每帧 `Transform`/`ExportClip`，接入 Concat 的合成与编码管线。

## 3.3 2D 场景与虚拟摄像机引擎（核心新增模块）

独立设计 `concat-scene`（场景）与 `concat-camera`（虚拟摄像机）模块，与传统线性视频剪辑时间轴解耦，通过统一工程数据层连接：

- 支持超大尺寸 2D 场景画布与无限外延空间。
- 多图层管理（背景、角色、道具、图片序列、前景遮罩）。
- 角色表情差分（立绘状态机切换）。
- 变换属性（位置、旋转、缩放、锚点、Alpha 透明度）及关键帧插值、缓动曲线（复用 `concat-core::Ease`）。
- 虚拟摄像机裁剪、缩放、旋转、视野实时预览与离屏渲染输出。

# 四、产品功能需求

## 4.1 视频剪辑（继承并完善 Concat 能力）

- 多轨道时间轴（视频轨、场景轨、角色语音轨、BGM/音效轨、字幕轨）。
- 素材导入（图片、视频、音频）、片段拖动、剪切、分割、复制、删除。
- 音频波形显示、音量调节、淡入淡出。
- 基础转场、滤镜、速度调整、关键帧。
- 撤销与重做、实时预览、可配置分辨率/帧率/码率的 MP4 导出。

## 4.2 完整 2D 场景编辑器（核心差异化功能）

- 场景画布与多场景管理（支持分幕/分镜切换）。
- 图层系统：背景层、角色层、道具层、图片序列层；支持排序、分组、锁定、隐藏。
- 画布直接拖拽定位、缩放与旋转。
- 角色表情差分系统（同一角色对象可在时间轴关键帧上快速切换立绘表情/姿势）。
- 关键帧与动画曲线（线性、贝塞尔、缓入缓出等）。
- 场景模板保存与复用。
- 最终输出画面由**虚拟摄像机画框**裁剪渲染，而非直接输出整张场景画布。

## 4.3 虚拟摄像机

- 摄像机画框可视化（安全框、中心准星、当前视野高亮）。
- 可配置输出分辨率与画幅比例（16:9、9:16 竖屏小剧场、4:3、21:9 等）。
- 摄像机位置（X/Y）、缩放（Zoom）、旋转（Rotation）及关键帧动画。
- 实时摄像机视野预览与最终成片渲染。
- 支持用户自定义创建、保存、命名和管理构图预设（不强制写死固定景别）。

## 4.4 运镜预设系统（重点功能）

运镜预设作为独立资产进行管理与复用。

- **第一批基础动作**：推近（Zoom In）、拉远（Zoom Out）、水平平移（Pan）、垂直平移（Tilt）、跟随角色（Follow Target）、组合运镜（Sequence）。
- **预设数据结构**：持续时间、起始/结束位置、起始/结束缩放、旋转参数、缓动曲线、插值方式、**是否相对当前摄像机状态（Relative Mode）**、可选目标角色/对象 ID。
- **相对运镜机制（关键）**：例如"推近"预设启用相对模式时，必须基于触发时刻摄像机的当前坐标与缩放比例计算增量，而非强制跳变到固定世界坐标。
- **交互与自动化**：支持创建、编辑、保存、复制、分类、收藏、删除、拖入时间轴、多运镜串联组合，以及通过 Agent/MCP 直接调用。

## 4.5 角色语音轨道与字幕系统

建立面向小剧场对白的高效工作流：

- **角色绑定语音轨**：每个角色可拥有独立语音轨道（一轨一角色），天然完成说话人归属。
- **语音与字幕解耦关联**：字幕与音频片段为两个独立对象，通过关联 ID 绑定；拖动语音片段时关联字幕自动同步位移，同时允许单独微调字幕文本、样式与起止时间戳。
- **角色视觉标识**：支持配置角色头像、角色专属字幕样式（字体、描边、配色、气泡/底框）。
- **本地 ASR 识别**：优先复用 `concat-speech`（whisper.cpp，支持 CPU），可选 `faster-whisper`（CUDA/INT8）；断网或无模型时完全可用。
- **标准格式互通**：支持 SRT、ASS 字幕文件的导入与导出。
- *(注：通用混音轨道的多人自动声纹聚类分离作为远期增强项，首版优先保证"分轨绑定角色 + 本地 Whisper 时间戳对齐"的极致稳定性。)*

## 4.6 资产管理器

作为软件核心底层模块之一：

- **存储架构**：使用 **SQLite** 管理资产元数据与索引，原始媒体文件独立存放在本地目录中，严禁将大型媒体二进制直接塞入 SQLite。
- **资产分类**：角色、角色表情、背景、道具、音频、BGM、音效、视频、字体、特效、运镜预设。
- **核心能力**：自动生成缩略图、标签管理、收藏、分类筛选、全文检索、拖拽入场景/时间轴、基于哈希的重复文件检测、文件移动路径追踪、工程引用关系查询、失效路径检测与一键重连、批量导入。

## 4.7 网络素材搜索器（可插拔模块）

必须完整支持无大模型（Offline/No-AI）模式：

- **基础搜索**：本地资产库检索（文件名、标签、关键词）+ 外部素材平台 API 检索与条件筛选。
- **AI 增强（可选）**：接入本地或云端 LLM 后，支持自然语言理解、自动关键词提取、跨源检索分发、语义重排与自动打标。
- **支持素材源**：Pixabay、Pexels、Openverse、Freesound、Wikimedia Commons。
- **合规元数据**：强制记录每份下载素材的来源平台、作者、许可证类型及原始 URL。

## 4.8 工作区管理系统

- **灵活布局**：面板自由拖动、尺寸调整、上下左右停靠、多面板标签页合并、独立浮动窗口、单面板最大化、显示/隐藏切换。
- **工作区预设**：提供"场景编辑"、"视频剪辑"、"字幕配音"、"资产管理"、"Agent 自动化"等初始模板，支持用户新建、复制、重命名、删除、导入/导出及恢复默认布局。
- **配置隔离**：工作区布局保存为独立 JSON 配置文件，与具体视频工程文件完全解耦；处理多显示器 DPI 变化及异常崩溃后的布局恢复。
- **Slint 约束**：Slint 无现成 docking；Phase 4 需先做布局 Spike，再决定自建或采用多窗口/标签替代。

## 4.9 现代化 UI 与 Duoasa-skill 工作流

- **视觉方向**：现代化深色设计语言，合理留白、清晰信息层级、高辨识度矢量图标、精致缩略图、一致圆角边框与流畅微交互。
- **设计红线**：禁止直接复制 Blender 或传统 Premiere 界面；禁止无意义大面积渐变或过度玻璃拟态；禁止牺牲画布与时间轴有效工作面积。
- **Duoasa-skill 集成**：在进入 Phase 4 完整界面设计前，检查环境中是否安装 `https://github.com/Duoasa/Duoasa-skill` 并阅读其完整 `SKILL.md`，结合实际 Slint 原型截图与交互测试进行迭代（若与小剧场高频操作效率冲突，以产品可用性为准）。

# 五、Agent 原生架构

Agent 是本软件的一等使用者，必须在核心层设计阶段优先实现结构化控制能力：

1. **多形态接口**：
   - **MCP Server**（核心标准协议，供 Claude Code / Codex / Cursor 等直接挂载）。
   - **CLI 命令行工具**（支持无头批量渲染、工程校验与脚本调用）。
   - **Python SDK**（后置为 MCP 薄封装，不作为首版交付物）。
   - **JSON 工程读写接口**。
2. **完整的操作覆盖**：
   - 工程生命周期：新建、打开、保存、校验、版本迁移。
   - 资产操作：查询本地库、搜索网络素材、导入素材、绑定角色表情。
   - 场景与摄像机编排：创建场景/图层、调整角色位置/缩放/透明度/表情差分、添加关键帧、创建虚拟摄像机、应用相对/绝对运镜预设。
   - 对白与时间轴：创建角色语音轨、导入配音、触发本地 ASR 生成字幕、调整时间轴片段。
   - 渲染导出：提交无头渲染任务、查询进度、导出指定规格 MP4。
3. **工程化接口契约**：
   - 严格的参数 Schema 校验与清晰错误码。
   - 完整的结构化操作日志。
   - 每次 Agent 修改自动封装为可撤销事务（支持一键 Undo 回滚）。
   - **严禁将 GUI 坐标模拟点击作为主要自动化手段**。

# 六、统一工程文件格式

以 `Concat` 原生 JSON 工程格式为基座进行向后兼容扩展，确保旧版基础剪辑数据结构依然有效。

- **核心数据结构**：
  - `meta`：工程名称、版本 (`schema_version`)、创建时间、全局设置。
  - `output`：默认输出分辨率、帧率、色彩空间、编码预设。
  - `assets_manifest`：工程引用的资产列表（优先通过全局唯一 `asset_id` 关联 SQLite 资产库，同时保留相对路径兜底）。
  - `characters`：角色定义、默认立绘、表情差分映射表、绑定语音轨 ID、字幕样式。
  - `scenes`：2D 场景列表，包含画布尺寸、背景与图层树（变换、关键帧、缓动曲线、表情切换事件）。
  - `cameras` & `camera_tracks`：虚拟摄像机参数、关键帧及引用的运镜预设实例。
  - `timeline`：多轨道时间轴（引用 `scene_id` 片段、音视频片段、关联字幕列表）。
- **可靠性机制**：支持 Schema 版本号检测与自动向上迁移、定时自动保存、崩溃恢复快照、JSON Schema 完整性校验。
- **实现路径**：`concat_project::doc` 使用 `serde_json::Value` 且保留未知字段（`extra`/`unread`），可直接加扩展字段；新增字段必须带 `#[serde(default)]`。

# 七、开发路线（Headless Core + MCP 优先重排版）

严格遵循**"先打通无头核心渲染与 Agent 协议，再完善重型桌面 UI"**的敏捷验证路线，确保每个阶段都有可运行的端到端产出。

## Phase 0：仓库审计、技术选型与架构设计
- 完成 `xmp777/Concat_camera` 代码基座审计与 Rust 生态组件调研。
- 完成许可证合规审查。
- 确定 `concat-scene`、`concat-camera` 与 `Concat` 管线的接口边界，输出扩展 JSON Schema 与 MCP 协议规范。
- **验收**：产出完整 `docs/` 设计文档集，确定最终技术选型清单。

## Phase 1：Headless 2D 场景与虚拟摄像机渲染核心 ✅（已基本完成）
- 已实现：`concat-scene`（场景/图层/相机轨道）、`concat-camera`（投影/预设）、`concat-studio`（无头渲染到 MP4）。
- **验收**：通过 CLI 读取一份手写测试 JSON，无头渲染并导出包含"背景 + 两个角色 + 道具"且按虚拟摄像机视野裁剪的 `output.mp4`。

## Phase 2：关键帧动画与相对运镜预设系统

## Phase 3：Agent 原生接口（MCP Server + CLI）

## Phase 5：多轨剪辑增强与工程可靠性闭环

- **验收**：可流畅完成多镜头场景拼接、音频混音与完整成片导出，异常关闭重启后可恢复工程。

## Phase 6：SQLite 资产库与角色语音/本地 ASR 字幕
- 实现 SQLite 资产库（缩略图生成、标签搜索、重复检测、失效路径修复、拖拽入场/入轨）。

## Phase 7：网络素材搜索器与可选 AI 增强
- 实现可插拔素材搜索 Provider（Pixabay、Pexels、Openverse、Freesound、Wikimedia Commons）及完整版权元数据记录。

- **验收**：断网或关闭所有 AI 配置时，本地与基础网络检索功能正常运行；开启 AI 后支持自然语言意图检索。
